## 2. 9 类 Agent 角色

| 类别 | 角色 | 成员数 | 职责 |
| --- | --- | --- | --- |
| 项目管理 | PM | 3 | 项目方向、里程碑、风险、资源分配 |
| 任务排期 | PL | 3 | 任务细分、排期、依赖分析、进度跟踪 |
| 记录 | REC | 3 | 会议记录、决策记录、变更日志、知识库 |
| 架构 | ARCH | 2 | 系统架构、IR 设计、模块边界、技术选型 |
| 算法 | ALG | 3 | 编译算法、类型系统、优化 pass、soundness |
| 开发 | DEV | 3 | 代码实现、bug 修复、重构、性能优化 |
| 测试 | QA | 3 | 测试设计、conformance、fuzzing、CI |
| 审查 | REV | 3 | 代码审查、设计审查、文档审查、合规审查 |
| Skill 管理 | SKL | 2 | Agent skill 编写、优化、评估、版本管理 |

## 3. 协作模式

### 3.1 串行协作（Sequential）

适用于：需求 → 设计 → 实现 → 测试 → 审查

```
PM 接收需求 → PL 任务分解 → ARCH 架构设计 → ALG 算法设计
→ DEV 实现 → QA 测试 → REV 审查 → REC 记录
```

### 3.2 并行协作（Parallel）

适用于：多维度研究/审查

```
PM 分派 → [ARCH + ALG + QA] 并行 → 汇总 → REV 审查
```

### 3.3 迭代协作（Iterative）

适用于：审查-修复循环

```
DEV 实现 → REV 审查 → DEV 修复 → REV 再审 → ... → 通过
```

### 3.4 升级协作（Escalation）

适用于：争议/风险升级

```
DEV ↔ REV 争议 → ARCH 仲裁 → PM 决策 → REC 记录
```

## 4. 决策机制

### 4.1 决策等级

| 等级 | 决策者 | 适用场景 | 示例 |
| --- | --- | --- | --- |
| L0 | 单个 Agent | 日常实现细节 | 变量命名、函数拆分 |
| L1 | 同类 Agent 共识 | 技术方案选择 | 算法选型、测试策略 |
| L2 | 跨类 Agent 协商 | 架构变更 | IR 修改、模块重组 |
| L3 | PM + ARCH + ALG | 重大设计变更 | 语言特性增减、ABI 变更 |
| L4 | 全体投票 + PM 终裁 | 项目级决策 | 版本发布、命名变更、scope 调整 |

### 4.2 决策流程

```
1. 提案（任何 Agent 可提）→ REC 记录
2. 评估（REV + 相关类 Agent）→ 风险评估
3. 讨论（L2-L4）→ 达成共识或投票
4. 决策（按等级）→ REC 记录
5. 执行（DEV）→ QA 验证
6. 回顾（REV）→ REC 归档
```

### 4.3 投票规则

- L4 决策需 2/3 多数同意
- PM 拥有否决权
- ARCH 拥有技术方案一票否决权（仅限架构相关）

## 5. 风险评估机制

### 5.1 风险等级

| 等级 | 定义 | 响应 |
| --- | --- | --- |
| R0-致命 | 阻塞项目继续 | 立即停工，PM 召集全员 |
| R1-高 | 阻塞当前里程碑 | 24h 内制定缓解方案 |
| R2-中 | 影响后续里程碑 | 7d 内制定缓解方案 |
| R3-低 | 影响质量但不阻塞 | 滚动修复 |

### 5.2 风险评估流程

```
任何 Agent 发现风险 → 提交风险报告（REC 记录）
→ PM 评估等级 → 分派给相关 Agent 制定缓解方案
→ REV 审查方案 → 执行 → REC 记录结果
```

## 6. Agent 间通信协议

### 6.1 通信渠道

- **worklog.md**：所有 Agent 共享的工作日志（append-only）
- **决策记录**：REC-Agent 维护的决策数据库
- **任务看板**：PL-Agent 维护的任务状态
- **风险登记册**：PM-Agent 维护的风险列表

### 6.2 通信格式

每个 Agent 完成任务后必须：

1. 读取 worklog.md 了解前序工作
2. 执行任务
3. 追加 worklog.md（不覆盖）
4. 更新相关看板/登记册

### 6.3 工作日志格式

```markdown
---
Task ID: <全局唯一 ID>
Agent: <Agent 名称>
Task: <任务描述>

Work Log:
- <具体步骤>

Stage Summary:
- <关键结果>
- <产出物路径>
- <风险/问题>
```
