## 历史决策记录

### DEC-001：语言定名为 Forge

- **日期**：2026-07-18
- **等级**：L4
- **参与者**：PM-A / ARCH-A / ALG-A / REC-A
- **提案者**：PM-A
- **讨论摘要**：需要为语言命名。Forge 与 Rust 金属主题呼应。
- **决策结果**：采用 Forge
- **理由**：金属工艺语义链（Rust→Forge）
- **风险**：未做商标/冲突调研
- **状态**：已撤销（DEC-004 替代）

### DEC-002：采用 MIR-first 架构

- **日期**：2026-07-18
- **等级**：L3
- **参与者**：PM-A / ARCH-A / ALG-A / ALG-B / REV-B
- **提案者**：ARCH-A
- **讨论摘要**：Rust 1.0 之前在 AST 上做 borrow check 痛苦（RFC #1211）。MVP 应从 day 1 上 MIR。
- **决策结果**：采用 MIR-first，所有静态分析在 MIR 上做
- **理由**：R1 报告强烈警告避开 AST-based 老路
- **风险**：MIR 实现复杂度高
- **状态**：已完成

### DEC-003：采用 NLL on MIR

- **日期**：2026-07-18
- **等级**：L3
- **参与者**：ARCH-A / ALG-B / REV-B
- **提案者**：ALG-B
- **讨论摘要**：NLL 比 lexical lifetime 更好用。R3 报告推荐 MVP 必须有 NLL。
- **决策结果**：采用 NLL（含 universal region + type tests + SCC 压缩）
- **理由**：R3 推荐 + RFC 2094 算法
- **状态**：已完成

### DEC-004：语言重命名为 Quench

- **日期**：2026-07-18
- **等级**：L4
- **参与者**：PM-A / ARCH-A / REV-C / REC-A
- **提案者**：PM-A
- **讨论摘要**：N1 报告发现 Forge 17+ 冲突。推荐 Quench（66/80）。
- **决策结果**：Forge → Quench
- **理由**：零冲突（N1 误判）+ 语义延续
- **风险**：N1 调研不充分
- **状态**：已撤销（DEC-006 替代）

### DEC-005：新增 19-project-meta.md 元信息 SSOT

- **日期**：2026-07-18
- **等级**：L3
- **参与者**：PM-A / ARCH-A / REV-C / REC-C
- **提案者**：REV-C
- **讨论摘要**：N2 报告发现元信息分散在 22 个文档中，3 P0 + 9 P1 不一致。
- **决策结果**：新增 19-project-meta.md 作为元信息单一来源
- **理由**：SSOT 原则，避免分散不一致
- **状态**：已完成

### DEC-006：语言重命名为 Fuller

- **日期**：2026-07-18
- **等级**：L4
- **参与者**：PM-A / ARCH-A / REV-B / REC-A
- **提案者**：PM-A
- **讨论摘要**：N3/N4 发现 Quench 致命冲突（QUENCH 商标 + crates.io 同名语言）。推荐 Fuller（29/40）。
- **决策结果**：Quench → Fuller
- **理由**：零冲突 + 锻造工具语义
- **风险**：语义链思维定势
- **状态**：已撤销（DEC-008 替代）

### DEC-007：放弃语义链命名策略

- **日期**：2026-07-18
- **等级**：L4
- **参与者**：PM-A / ARCH-A / REC-A
- **提案者**：PM-A
- **讨论摘要**：用户指出命名不必为了语义放弃更好选择。N5 调研 15 门成功语言，发现无一采用语义链命名。
- **决策结果**：放弃"金属工艺语义链"约束，采用基于独特性/记忆性/品牌个性的命名策略
- **理由**：实证数据压倒语义直觉
- **状态**：已完成

### DEC-008：语言重命名为 Landin

- **日期**：2026-07-18
- **等级**：L4
- **参与者**：PM-A / ARCH-A / ALG-A / REV-B / REC-A
- **提案者**：PM-A
- **讨论摘要**：N5 推荐 Landin（38/50）。用户指出不必为人名，但 Landin 核心优势是零冲突+故事独立成立。
- **决策结果**：Fuller → Landin
- **理由**：零冲突 + 已故无需同意 + 故事可独立成立（"The Next 700 Programming Languages"）
- **风险**：用户可能仍不满意命名
- **状态**：已完成

### DEC-009：自举目标从 v0.1 推迟到 v0.3

- **日期**：2026-07-18
- **等级**：L4
- **参与者**：PM-A / ARCH-A / PL-A / REC-A
- **提案者**：PM-A
- **讨论摘要**：R8 报告证明 15 月自举不可达。1 人全职实际需 30-54 月。
- **决策结果**：v0.1 = 仅 stage 0（不自举，27-40 月）；v0.3 = 自举完成（43-64 月）
- **理由**：R8 工作量重估 + R4 业界对照
- **状态**：已完成

### DEC-010：Stage 0 frozen blob 改用预编译二进制

- **日期**：2026-07-18
- **等级**：L3
- **参与者**：ARCH-A / PM-A / REV-B
- **提案者**：ARCH-A
- **讨论摘要**：R8 报告指出 LLVM bitcode 跨版本不稳定。
- **决策结果**：从 LLVM bitcode 改为预编译二进制 + Rust 源码双备份
- **理由**：LLVM bitcode backward compatible but NOT forward compatible
- **状态**：已完成
