# Stage 15.61 — LLVM Backend Drop Glue Emission Fix

> **Author**: redskaber
> **Date**: 2026-08-02
> **Version**: v0.186.0 → v0.187.0
> **Process**: stage-committee-process.md v3.23 §11.3 (LLVM doc sync)
> **Scope**: Documents the LLVM backend fix for drop glue function emission.

## 1. Problem

The LLVM backend (`codegen_crate_to_module` in `src/codegen/mod.rs`) was
missing a call to `emit_drop_glue_functions`. This caused `--emit-obj`,
`--emit-bin`, and `--run` to fail at link time with:

```
/usr/bin/ld: undefined reference to `drop_adt_0'
collect2: error: ld returned 1 exit status
```

The text backend (`codegen_crate`) already called `emit_drop_glue_functions`
at line 167, but the LLVM backend (line 281+) did not — the function was
only added to the text backend in Stage 15.57.

## 2. Fix

Added `emit_drop_glue_functions` call to `codegen_crate_to_module`,
positioned after `emit_dyn_trait_ptrs` and before `codegen_from_mir`
(matching the text backend's ordering):

```rust
emit_vtables(&result.trait_resolver, &result.interner, &mut emitter);
emit_dyn_trait_ptrs(&result.trait_resolver, &result.interner, &mut emitter);
// Stage 15.61: Emit drop glue functions in the LLVM backend too.
emit_drop_glue_functions(
    &result.trait_resolver,
    &result.interner,
    &result.fn_name_by_def_id,
    &mut emitter,
);
codegen_from_mir(
    &result.mirs,
    &result.body_metas,
    &result.fn_name_by_def_id,
    &result.fn_sigs,
    &result.interner,
    &mut emitter,
);
```

## 3. Drop Glue Function Format

For each type `T` with `impl Drop for T`, the drop glue function is:

```llvm
declare void @landin_<Type>_drop(ptr %self)

define void @drop_adt_<DefId>(ptr self) {
  call void @landin_<Type>_drop(ptr self)
  ret void
}
```

Where:
- `<DefId>` is the TYPE's DefId (not the impl block's DefId — Stage 15.60 fix).
- `<Type>` is the struct/enum name (e.g., `Counter`).
- The function takes `ptr self` (a pointer to the value).
- The function calls the user's `Drop::drop` method with the pointer.

## 4. Call Site

`TerminatorKind::Drop` codegen (`src/codegen/terminator.rs`) generates:

```llvm
call void @drop_adt_<DefId>(ptr %loc_N)
br label %bbM
```

Where `%loc_N` is the alloca pointer for the place (Stage 15.61 fix: pass
`EmitType::OpaquePtr`, not the place's value type).

## 5. Verification

After the fix, the LLVM backend produces correct object files that link
successfully:

```bash
$ ./target/release/landin-stage0 --emit-bin test_drop.lin -o test_drop.bin
info: object file written to /tmp/test_drop.lin.o
info: executable written to /tmp/test_drop.bin

$ ./test_drop.bin; echo "exit=$?"
exit=42
```

## 6. Architecture Compliance

Per §16 (interface isolation):
- `emit_drop_glue_functions` reads only `TraitResolver`, `Rodeo` (interner),
  and `fn_name_by_def_id` — all pre-built data structures, no HIR lookup.
- The LLVM backend call matches the text backend call exactly (same arguments,
  same ordering relative to other emission passes).

Per §23 (API naming):
- `emit_drop_glue_functions` follows the `emit_<noun>` pattern (rule 7).
- The function is a free-function entry point (rule 1).

Per §1.0 原則 3 "显式 > 隐式":
- The drop glue function is explicitly emitted (not auto-generated by LLVM).
- The call site is explicit in the MIR (`TerminatorKind::Drop`).
