## 3. Gap 详细分析

### 3.1 P0 — Conformance scope (Critical)

**问题**: v0.1 需要 5,000 个 conformance tests，当前仅 600 个 (00-parse category)

**根因**:
- Stage 9 计划 (plan-9.1.md) 基于 `17-conformance-suite.md` §2 的 600 parse tests 目标
- 但 §5.1 明确要求 8 categories 共 5,000 tests
- Stage 9.1 的 systematic-review-v0156.md 仅检查了 00-parse 目录结构，未对照 §5.1 全量

**影响**: v0.1 release gate 未达成 — 当前 "v0.1 RC" 宣布过早

**处理方案**:
- 重新定位当前状态为 "Stage 9.12 — Parse conformance milestone (600/600)"
- 制定 Stage 10 计划，补全剩余 7 categories (4,400 tests)
- 每个子阶段扩展 1 category

**时间安排**: Stage 10.1-10.7 (7 sub-stages), 每阶段 ~1 个 category

### 3.2 P1 — Conformance test format (High)

**问题**: 当前 .lin 文件格式与 spec 不一致

**当前格式** (Stage 9 采用):
```
//! PASS
//! category: literals
//! description: decimal integer literal
//! source: lexer regression
fn f() { let _ = 42; }
```

**Spec 格式** (`17-conformance-suite.md` §3):
```
// CATEGORY: parse
// DESCRIPTION: Decimal integer literals
// EXPECTED: compile_ok
fn main() { ... }
```

或 Fail 测试:
```
// EXPECTED: compile_error
// ERROR_CODE: E0308
// ERROR_PATTERN: expected `i32`, found `&str`
```

**根因**:
- Stage 9.1 设计时基于现有 `empty_hex.lin` 的 `//!` 格式
- 未对照 §3 spec 的 `//` 格式 + `EXPECTED` 字段 + `ERROR_CODE` 字段

**影响**:
- format 不兼容 §3 spec
- 缺少 `EXPECTED` 字段 (compile_ok/compile_error/run_ok)
- 缺少 `ERROR_CODE` 字段 (E0xxx)
- 缺少 `EXPECTED_STDOUT` / `EXPECTED_EXIT_CODE` 字段 (for run tests)

**处理方案**:
- Stage 10.0: 格式迁移 — 将 600 个现有 .lin 文件从 `//!` 格式迁移到 `//` 格式
- 添加 `EXPECTED` 字段 (现有 PASS→compile_ok, FAIL→compile_error)
- 保持向后兼容: runner 同时支持 `//!` 和 `//` 格式

**时间安排**: Stage 10.0 (1 sub-stage, 格式迁移 + runner 升级)

### 3.3 P1 — CLI capabilities (High)

**问题**: 当前 CLI 仅支持 `--emit-tokens` 和 `--emit-ast`，不支持 compile/codegen/run

**当前 CLI** (`src/bin/main.rs`):
- `--emit-tokens`: 输出 token 流
- `--emit-ast`: 输出 AST 摘要
- 无 `--compile` / `--run` / `--emit-llvm-ir` 选项

**Spec 需求** (`17-conformance-suite.md` §3):
- `compile_ok`: 完整编译通过 (lex + parse + resolve + typeck + borrowck + codegen)
- `compile_error`: 编译失败 (某阶段报错)
- `run_ok`: 编译 + 运行 + 验证 stdout/exit-code

**根因**:
- CLI 在 Stage 0 (早期) 实现，仅覆盖 lexer + parser
- Stage 1-8 后端 (HIR/MIR/typeck/borrowck/codegen) 已实现但未通过 CLI 暴露
- conformance runner 通过 `--emit-ast` 间接验证 parse，无法验证 typecheck/borrowck/codegen

**影响**:
- 无法运行 01-typecheck / 02-borrowck / 03-codegen / 04-e2e 测试
- conformance suite 只能覆盖 00-parse

**处理方案**:
- Stage 10.0: CLI 升级 — 添加 `--compile` (full pipeline) + `--emit-llvm-ir` + `--run` 选项
- 利用 driver API (`landin_compiler::driver::compile`) 实现完整编译
- runner 升级支持 compile_ok/compile_error/run_ok 验证

**时间安排**: Stage 10.0 (与格式迁移合并)

### 3.4 P2 — Missing conformance categories (Medium)

**问题**: 7 个 conformance categories 缺失

**当前**: 仅 `tests/conformance/00-parse/`
**需要**: `01-typecheck/` + `02-borrowck/` + `03-codegen/` + `04-e2e/` + `05-soundness/` + `06-stdlib/` + `07-integration/`

**处理方案**: Stage 10.1-10.7 逐个 category 创建 + 扩展

**时间安排**: 7 sub-stages

### 3.5 P2 — Runner capabilities (Medium)

**问题**: 当前 runner 仅支持 parse 验证 (通过 `--emit-ast` 检查 parse errors)

**需要**: runner 升级支持 typecheck/borrowck/codegen/e2e 验证

**处理方案**: Stage 10.0 runner 升级 (与 CLI 升级合并)
