## 2. 已完成工作（Stages 16.00–16.18）

### 2.1 Sound Copy 检测（Stages 15.99, 16.02–16.06）

**问题**: `ty_is_copy` 对所有 Adt 类型返回 `true`（不健全）。

**解决方案**: 字段级 Copy 推导
- `TraitResolver.derived_copy_types: HashSet<DefId>` — 所有字段都是 Copy 且无 `impl Drop` 的结构体/枚举
- 不动点迭代处理嵌套结构体
- `is_copy_builtin()` 先检查 `derived_copy_types`，再检查显式 `impl Copy`
- `ty_is_copy` 标记 `#[deprecated]`
- MIR lowerer 使用 `Operand::Move`（替代 `Operand::Copy`）用于 let 绑定、返回、调用参数

**测试**: +10 集成测试 + 3 个现有测试更新

### 2.2 Task 3: TraitResolver Keys（Stages 16.07–16.11）

**问题**: `impl_by_trait_and_type: HashMap<(Spur, Spur), DefId>` 键不类型安全，不支持泛型。

**解决方案**: DefId 键控查找
- `impls_by_def_ids: HashMap<(DefId, DefId), DefId>` — DefId 键控的 impl 查找
- `vtables_by_def_ids: HashMap<(DefId, DefId), Vtable>` — DefId 键控的 vtable 查找
- `populate_def_id_keyed_maps()` 后置处理 — 解决 HIR 迭代顺序问题
- `find_impl_by_def_ids()`, `implements_by_def_ids()`, `find_vtable_by_def_ids()` — 新查询方法
- `find_trait_def_id()`, `impl_methods_by_def_ids()` — 辅助方法
- 5 个 Spur 键控方法标记 `#[deprecated]`

**测试**: +33 集成测试

### 2.3 Task 10: 闭包重设计 Steps 1+2（Stages 16.13–16.14）

**问题**: 内联闭包调用方式有代码膨胀、无优化、MIR 污染等问题。

**解决方案**: Strategy A（合成 `call` 函数）基础设施
- `SynthesizedClosureFunction` 结构体 — 闭包元数据
- `synthesized_closure_functions` side-table on `MirLowerCtxt`
- `allocate_closure_def_id()` — 唯一 DefId 分配（修复共享 DefId bug）
- `build_synthesized_closure_mir_body()` — 构建独立 MirBody
- `synthesized_closure_mir_bodies` field on `CompileResult`
- `MirBody.def_id` — 永久改进，用于 codegen 函数名解析

**测试**: +24 集成测试

## 5. 架构决策记录

### 5.1 字段级 Copy 推导（Stage 16.06）

**决策**: 不迁移 199 个测试文件添加 `impl Copy`，而是实现字段级推导。

**理由**: 
- 用户友好（`struct Point { x: i32, y: i32 }` 直觉上是 Copy）
- 健全（保守推导，只有所有字段都是 Copy 且无 `impl Drop` 才推导）
- §16 合规（TraitResolver 读取 HIR，BorrowChecker 查询无需 HIR）

### 5.2 DefId 键控查找（Stage 16.07）

**决策**: 并行 DefId 键控 map，渐进迁移，最终废弃 Spur 键控方法。

**理由**:
- 类型安全（DefId 是唯一标识符，非字符串哈希）
- 无需 interner（调用者不需要 `&Rodeo`）
- 为泛型 SubstsRef 支持做准备

### 5.3 闭包 Strategy A（Stage 16.13）

**决策**: 合成 `call` 函数，而非内联闭包体。

**理由**:
- 匹配设计文档 `07-codegen.md` §8.1-8.2
- 匹配 Rust 的方法
- 更清晰的 MIR，支持优化

### 5.4 MirBody.def_id（Stage 16.17）

**决策**: 在 MirBody 上添加 `def_id: Option<DefId>` 字段。

**理由**:
- 永久改进，用于 codegen 函数名解析
- 替代脆弱的字符串搜索
- §16 合规（数据携带在 IR 上，不从 HIR 查找）
