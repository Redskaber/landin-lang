> **Author**: redskaber
> **Date**: 2026-07-28
> **Version**: v0.35.0 (current) → v0.1.0 (target release)
> **Process**: stage-committee-process.md v3.21 (§13.4 + §25)
> **Status**: Draft

---

## Executive Summary

The Landin compiler has reached an **impressive breadth of front-end + codegen infrastructure** (lexer, parser, HIR, MIR, type-checker, NLL borrow-checker skeleton, TextEmitter + LLVMSysEmitter, `--run` execution pipeline, format args). The 5,026-test conformance suite is a major asset.

**However, the prior `docs/develop/v0/stage-12/v0.1-release.md` claim of "v0.1 GATE REACHED" (2026-07-26) is premature.** A deeper audit against the v0.1 design intent (`docs/lang-design/12-roadmap.md` §1 + `13-stage1-feature-whitelist.md` §4) shows:

1. **Soundness regressions silently accepted** — Stage 13.25 flipped 229 conformance tests from `compile_error` to `compile_ok` because the NLL checker is "too permissive (doesn't catch simultaneous borrows)". The design-intended unsound programs are now silently accepted.
2. **Three "dead_code" subsystems claimed as complete but not wired up** — `lifetime_elision`, `drop_elaboration`, and `region_inference` are all `#[allow(dead_code)]` in `src/typeck/mod.rs`, `src/borrowck/mod.rs`. Region inference is a documented no-op (`"all regions are currently Erased"`).
3. **Conformance runner does not verify runtime behavior** — `tests/conformance/run_all.py` parses `run_ok` headers but does not actually invoke `--run` for them; it falls through to `--compile` like `compile_ok`. All 5,026 "passing" tests only verify compilation, not execution.
4. **`self.x` field access crashes codegen** (Stage 13.17 known limitation, deferred to Stage 13.18) — this breaks most OOP-style code and trait method bodies.
5. **No real standard library** — the 502 `06-stdlib` conformance tests don't test the stdlib; they test user-defined types named `Vec`/`String` (e.g., `struct Vec<T>{data:[T;0],len:i32}`). The "stdlib" is a Rust-side `StdlibFacade` with type names only — there are no `core`/`alloc`/`std` crates written in Landin.
6. **Missing v0.1-mandatory features** per `13-stage1-feature-whitelist.md` §4: `?Sized`, HRTB, two-phase borrows (method-call subset), disjoint closure captures (RFC 2229), drop check (`#[may_dangle]`), associated type normalization with termination guarantee.
7. **Three version strings disagree** — README.md shows v0.27.1, Cargo.toml shows v0.35.0, RELEASE_NOTES.md shows v0.25.3. The worklog ends at Stage 13.29 (v0.30.0); Stages 13.30-13.34 happened without worklog updates.

**Verdict: NO-GO for v0.1 release.** See §4 for the P0 blocker list and §5 for the Stage 14.x plan to close the gaps.

### 2.1 Lexical Analysis (Stage 0)

- **Test coverage**: 600 `00-parse` conformance tests (100% per matrix.md), plus inline lexer_tests.rs.
- **Status**: ✅ **Complete** — exceeds §1 design intent.

### 2.2 Parsing (Stage 0)

### 2.5 MIR (Stage 2)

- **Design intent** (`06-mir.md`): CFG per function body; `BasicBlock`/`Statement`/`Terminator`/`Place`/`Rvalue`/`Operand`; types matching rustc master (`Fake(FakeBorrowKind)`, `Coroutine`, `RawPtr(RawPtrKind)`, etc.).

- **Status**: ✅ **Complete** for v0.1 data structure. Lowering covers control flow, ADT layout, closure capture, pattern bindings, overflow asserts, field resolution.

### 2.6 Type Checking (Stage 2)

- **Design intent** (`03-type-system.md` §4): constraint-based inference (Odersky-Wadler-Wehr 1995); unification; trait resolution 3-phase (Evaluation + Selection + Fulfillment + canonical query, depth=128); monomorphization; associated type normalization with termination guarantee; integer fallback to i32.
- **Current implementation**: `src/typeck/{mod,checker,error,unify,predicates,tables,lifetime_elision}.rs`. `src/traits/{mod,resolver,vtable,builtin,object_safety}.rs`.
  - Constraint-based unification ✅ (UnificationTable)
  - TraitResolver ✅ (collects trait defs + impls + builds dispatch tables)
  - **Stage 8.1 lifetime elision: ⚠️ module exists but `#[allow(dead_code)]` — not wired into checker.rs**
  - Coherence checking ✅ (Stage 5.18)
  - Impl completeness ✅ (Stage 5.19)
  - **Trait resolution 3-phase canonical query: ❌ not implemented** — current TraitResolver is single-pass collection, not the design's Evaluation/Selection/Fulfillment pipeline with canonical query.
  - **Associated type normalization with termination guarantee: ❌ not implemented** — no associated type machinery in typeck.
  - Integer fallback ✅ (default_unresolved → i32/f64)
  - **`?Sized` partial support: ❌ not implemented** (per v0.1-release.md §5 Known Limitations)
  - **HRTB `for<'a>`: ❌ not implemented** (per v0.1-release.md §5)
- **Test coverage**: 1020 `01-typecheck` conformance tests (compile-only) + typeck_tests.rs.
- **Status**: ⚠️ **Partial** — basic inference works for the conformance suite, but 3 of the v0.1-mandatory features (canonical query, associated type normalization, `?Sized`/HRTB) are missing.

### 2.7 Borrow Checking (Stage 2)

- **Design intent** (`04-ownership-borrowing.md` §2-4): **NLL on MIR** with universal region + type tests + universe mechanism + SCC compression (per R5/R6); two-phase borrows method-call subset (§2.4); disjoint closure captures (RFC 2229); drop check with `#[may_dangle]` (§5); liveness + maybe-init analysis.
- **Current implementation**: `src/borrowck/{mod,borrow_set,liveness,copy_semantics,move_tracker,place_path,region_inference,drop_elaboration,error}.rs`.
  - **NLL: ⚠️ single-pass forward walk with pre-computed last-use map** — the implementation comment in `mod.rs` line 113 admits: *"It's correct for straight-line code and most loop patterns. The only case it gets wrong is when a borrow's last use is inside a loop body but the borrow was created outside the loop — in that case the borrow is killed after the first iteration's last use, producing a false-positive borrow error on the second iteration. This is a known limitation; full fixpoint dataflow is Stage 3."*
  - **Stage 13.25 NLL flip: ❌ soundness regression** — 229 conformance tests flipped from `compile_error` to `compile_ok` because "NLL borrow checker is more permissive than the old lexical borrow checker" and "doesn't catch simultaneous borrows". Acknowledged as "known v0.2 limitation" but this violates the v0.1 design intent of full NLL soundness.
  - **Region inference (TD-015): ❌ dead_code** — `#[allow(dead_code)] mod region_inference;` in `src/borrowck/mod.rs:42`. The run_region_inference comment admits: *"Since all MIR regions are currently Erased (mapped to 'static vid 0), the inference produces empty point sets for all regions. The universal region check passes because empty ⊆ empty. This is the expected no-op behavior."*
  - **Two-phase borrows: ❌ not implemented** — no `MutBorrowKind::TwoPhaseBorrow` enum; no reservation/activation point tracking.
  - **Disjoint closure captures (RFC 2229): ❌ not implemented** — `src/mir/lower/closure_capture.rs` does whole-local capture, not field-level disjoint.
  - **Drop elaboration (TD-015 step + §5): ❌ dead_code** — `#[allow(dead_code)] mod drop_elaboration;` in `src/borrowck/mod.rs:33`. No `Drop::drop` method invocation codegen.
  - **Drop check `#[may_dangle]`: ❌ not implemented** — attribute parsed but no dropck logic.
- **Test coverage**: 800 `02-borrowck` conformance tests (compile-only), but **229 of these were unsoundly flipped to compile_ok in Stage 13.25**.
- **Status**: ❌ **Missing v0.1-mandatory soundness guarantees**. The "NLL" label is technically wrong — it's a single-pass last-use approximation that under-rejects (loops) AND over-accepts (simultaneous borrows).

## 4. Release-Readiness Verdict

### Capability counts

- **Total capabilities inventoried**: 20 (§2.1 through §2.20)
- **Complete**: 6 (§2.1 Lexer, §2.2 Parser, §2.3 AST, §2.5 MIR, §2.8 TextEmitter, §2.9 LLVMSysEmitter)

- **Missing**: 3 (§2.15 Stdlib, §2.16 Region inference, §2.20 CLI toolchain)

### P0 blockers (must close before v0.1 release)

1. **GAP-0** — Process gap (worklog out of date, version strings disagree)
2. **GAP-1** — NLL soundness regression (229 tests flipped)
3. **GAP-2** — Region inference dead_code
4. **GAP-3** — Drop elaboration dead_code
5. **GAP-4** — Lifetime elision dead_code
6. **GAP-5** — `self.x` field access crashes codegen
7. **GAP-6** — Two-phase borrows missing
8. **GAP-8** — `run_ok` conformance tests not actually run
9. **GAP-9** — No real standard library
10. **GAP-21** — 229 conformance tests unsoundly flipped (couples with GAP-1)
11. **GAP-30** (couples with P0) — Trait method dispatch via dyn not verified end-to-end

### Recommendation: **NO-GO for v0.1 release**

The compiler has impressive infrastructure breadth (lexer through LLVM object files + execution pipeline + format args), but the v0.1 design intent is **not met** because:

1. **Soundness** — The borrow checker is structurally a single-pass last-use approximation, not the design's NLL with universal regions + type tests + universe + SCC. Stage 13.25's mass flip of 229 unsound programs to `compile_ok` is a clear soundness regression that must be reversed.
2. **Feature completeness** — 4 of the `13` §4.1 v0.1-mandatory features are dead_code (region inference, drop elaboration, lifetime elision) or missing (two-phase borrows, disjoint closure captures, `?Sized`, HRTB, associated type normalization, canonical query).
3. **Standard library** — There is no Landin-written standard library. The "stdlib" conformance tests are tautological.
4. **Conformance rigor** — The runner doesn't verify runtime behavior, fuzz tests are missing, soundness tests lack REFERENCES, and 502 stdlib tests are tautological.
5. **Toolchain** — Mini-cargo, `landin test`, `landin fmt`, `landin doc` are all absent.

### Path to GO

Close the 11 P0 blockers + verify via re-audit, then re-evaluate. Estimated effort: **6-10 weeks of focused work** (per the L/M/S estimates in §3, with parallelization).
