## 1. Problem Statement

Stage 15.37 attempted to switch the driver from the legacy borrow-check
path (`check_mir_body`) to the dataflow path
(`check_mir_body_with_dataflow`). The switch regressed **112 conformance
tests** — all cases where the dataflow path accepts a program that the
legacy path rejects.

Stage 15.38 built a diagnostic tool
(`tests/v0/stage15/plan/borrowck_comparison_diagnostic_tests.rs`) that
compares the two paths on all 5216 conformance tests. The results:

| Category | Count | Meaning |
|----------|-------|---------|
| AGREE-OK | 4829 | Both paths accept (valid program) |
| AGREE-ERROR | 86 | Both paths reject with same errors |
| **LEGACY-STRICTER** | **112** | Legacy rejects, dataflow accepts (GAP-1) |
| **DATAFLOW-STRICTER** | **1** | Dataflow rejects, legacy accepts (false positive!) |
| DIFFERENT-ERRORS | 0 | Both reject, different error counts |

The 112 LEGACY-STRICTER cases are the GAP-1 conflict (expected). The
**1 DATAFLOW-STRICTER case is unexpected** — it means the dataflow path
has a false positive on a valid program (`e2e-runok-132-state-machine.lin`).

## 2. Root Cause Analysis

### 2.1 The project's "NLL" is actually lexical lifetimes

Examining the 112 LEGACY-STRICTER cases reveals that the project's
borrow checker is NOT doing real Non-Lexical Lifetimes (NLL). It's
doing **lexical lifetimes with a last-use optimization that only kicks
in for locals that ARE read**. Specifically:

| Pattern | Real Rust NLL | Project's "NLL" (legacy path) | Dataflow path |
|---------|---------------|-------------------------------|---------------|
| `let r1 = &mut x; let r2 = &mut x;` (r1 never read) | ✅ allowed (r1 dead, borrow expires) | ❌ rejected (borrow lingers) | ✅ allowed (correct NLL) |
| `{ let r = &x; } x = 2;` (r's scope ended) | ✅ allowed (scope ended, borrow expires) | ❌ rejected (borrow lingers) | ✅ allowed (r dead, borrow expires) |
| `while x > 0 { let r = &x; x -= 1; }` (r never read) | ✅ allowed (r dead each iteration) | ❌ rejected (borrow lingers) | ✅ allowed (r dead, borrow expires) |
| `let r = &x; println(); x = 2;` (r read by println?) | ✅ allowed (r dead after println) | ❌ rejected (borrow lingers) | ✅ allowed (r dead, borrow expires) |

The legacy path's behavior: a borrow stays alive until the **end of the
lexical scope** of its `ref_local`, UNLESS the `ref_local` is read
(in which case the last-use optimization kicks in and the borrow dies
after the last read). This is lexical lifetimes with a partial last-use
optimization — NOT real NLL.

The dataflow path does real NLL: a borrow dies when its `ref_local` is
no longer live (regardless of scope).

### 2.2 Why the legacy path "accidentally" implements lexical lifetimes

The legacy `compute_last_use_map` records the last program point where
each local is **read**. A local that is never read (like `r1` in
`let r1 = &mut x; let r2 = &mut x;`) is NOT in the map. The
`kill_expired_borrows` function only kills borrows whose `ref_local`
has a "last use" at the current point — so a never-read local's borrow
is NEVER killed by the kill path. It stays alive as a "stray" until the
borrow set is cleared at function return.

This "stray borrow" behavior is what makes the legacy path reject the
GAP-1 patterns — the stray borrow conflicts with the new borrow.

### 2.3 The DATAFLOW-STRICTER false positive

The 1 DATAFLOW-STRICTER case is `e2e-runok-132-state-machine.lin`, a
valid `run_ok` program with `&mut self` method call chains:

```rust
let mut m = Machine::new();
m.start();       // &mut self borrow on m
m.tick();        // &mut self borrow on m
if i == 5 { m.pause(); }   // &mut self borrow on m
```

The dataflow path rejects this because it kills the `&mut self` borrow
from `m.start()` before `m.tick()` is called (the borrow's `ref_local`
— a temporary — is dead after `m.start()` returns). The legacy path
keeps the borrow alive longer (lexical lifetimes), so `m.tick()` succeeds.

This is a **false positive** in the dataflow path — the program is valid
but the dataflow path rejects it. The root cause is that `&mut self`
method calls lower to a borrow on a temporary that's immediately dead,
and the dataflow path correctly (per NLL) kills that borrow, but the
next method call needs the borrow to be gone (not just dead — actually
killed from the borrow set).

Wait, actually — if the borrow is killed, the next `&mut self` should
succeed (no conflict). So why does the dataflow path reject it?

Let me re-examine. The issue might be that the dataflow path kills the
borrow TOO LATE — after the next method call's borrow is already created.
Or the issue might be in how `&mut self` is lowered (the temporary might
not be tracked correctly).

This needs further investigation. For the design decision, the key
takeaway is: **the dataflow path has at least one false positive on
valid method-call-heavy code**, which means switching the driver would
not just relax GAP-1 but also break valid programs.

## 3. Reconciliation Options

### Option A: Adopt real Rust NLL (flip the 112 tests)

**What**: Change the 112 LEGACY-STRICTER conformance tests from
`compile_error` to `compile_ok`. Switch the driver to
`check_mir_body_with_dataflow`. Fix the 1 DATAFLOW-STRICTER false
positive (investigate the `&mut self` method call issue).

**Pros**:
- Correct NLL semantics (matches real Rust).
- Simpler mental model (borrows die at last use, not scope end).
- Removes the "stray borrow" hack from the legacy path.

**Cons**:
- Regresses (relaxes) 112 conformance tests — they become valid.
- Requires fixing the `&mut self` false positive (unknown effort).
- Changes the project's soundness posture (previously rejected programs
  are now accepted).
- The 112 tests were deliberately set to `compile_error` in Stage 14.81
  (GAP-1 fix) — flipping them back reverses that decision.

**Effort**: 1-2 weeks (fix the false positive + flip tests + switch driver).

### Option B: Keep lexical lifetimes (modify dataflow path)

**What**: Modify `kill_expired_borrows_dataflow` to NOT kill a borrow
when its `ref_local` is dead but still "in scope". Specifically: a
borrow is killed only when its `ref_local` was READ at some point AND
is now past its last read. This preserves the legacy path's lexical
lifetimes behavior while using the dataflow infrastructure for
loop/conditional correctness.

**Implementation**: Add a "was ever read" check to
`kill_expired_borrows_dataflow`. A borrow's `ref_local` is killed only
if it appears in the `Use` set of any block reachable from the current
point. This requires computing a "ever read" set (a forward dataflow
analysis, or simply a pre-computed set of all read locals).

**Pros**:
- Preserves GAP-1 soundness (112 tests stay `compile_error`).
- Uses the dataflow infrastructure (compute_liveness, compute_live_after_point).
- Fixes the actual NLL soundness bugs (loops, conditionals) that the
  legacy path gets wrong.
- Allows the driver switch to proceed without regressing conformance.
- The 1 DATAFLOW-STRICTER false positive is avoided (the lexical
  lifetimes behavior keeps `&mut self` borrows alive long enough).

**Cons**:
- Not standard NLL — the project's borrow checker remains "lexical
  lifetimes with last-use optimization".
- The "was ever read" check is a heuristic that might have edge cases.
- Future migration to real NLL is still deferred.

**Effort**: 3-5 days (implement + test the "was ever read" check).

### Option C: Hybrid (dataflow for loops/conditionals, legacy for straight-line)

**What**: Use the dataflow path only for basic blocks that are part of
a loop or conditional (i.e., blocks with multiple predecessors or
multiple successors). Use the legacy path for straight-line code.

**Implementation**: Detect "is this block in a loop/conditional context?"
by checking if any block in the CFG has ≥2 predecessors or ≥2 successors.
If so, use the dataflow path for the whole function. Otherwise, use the
legacy path.

**Pros**:
- Best of both worlds: dataflow correctness for loops/conditionals,
  legacy strictness for straight-line code.
- Preserves GAP-1 for straight-line patterns (the 112 cases).
- Fixes the loop/conditional soundness bugs.

**Cons**:
- Complex to implement (two code paths, CFG analysis).
- The boundary between "loop/conditional" and "straight-line" is fuzzy
  (e.g., a straight-line block inside a loop).
- The 1 DATAFLOW-STRICTER false positive might still occur if the
  method-call-heavy code is in a loop/conditional context.

**Effort**: 1-2 weeks (CFG analysis + dual code paths + testing).

## 4. Recommendation

**Option B** is the recommended path forward.

**Rationale**:

1. **Preserves soundness posture**: The project deliberately decided
   (Stage 14.81) that GAP-1 patterns should be `compile_error`. Option B
   respects this decision. Options A and C would relax it.

2. **Uses existing infrastructure**: The dataflow infrastructure
   (`compute_liveness`, `compute_live_after_point`,
   `kill_expired_borrows_dataflow`) is already built and tested (Stages
   15.35-15.36). Option B adds a small "was ever read" check on top.

3. **Fixes real bugs**: The legacy path IS unsound for loops/conditionals
   (a borrow created before a loop and used inside the loop body should
   survive across iterations). Option B fixes this while preserving
   GAP-1 for straight-line code.

4. **Avoids the false positive**: The 1 DATAFLOW-STRICTER case
   (`&mut self` method calls) is avoided because Option B's lexical
   lifetimes behavior keeps borrows alive longer.

5. **Lowest effort**: 3-5 days vs 1-2 weeks for Options A/C.

6. **Reversible**: If the project later decides to adopt real NLL
   (Option A), the "was ever read" check can be removed — it's a
   small, isolated change.

**Per §1.0 原則 1 "长期 > 短期"**: Option B is the right long-term
design for now — it fixes the real soundness bugs without changing the
project's soundness posture. Future migration to real NLL (Option A)
remains possible when the project is ready to revisit the GAP-1 decision.

**Per §1.0 原則 5 "报错 > 静默"**: Option B preserves the "stray borrow"
behavior that makes GAP-1 patterns error — this is the safer choice.

## 5. Implementation Plan (Option B)

### 5.1 The "was ever read" check

Add a pre-computed set `ever_read: HashSet<LocalId>` to the dataflow
borrow-check entry point. This set contains every local that is read
ANYWHERE in the MIR body (i.e., the union of all `Use[bb]` sets).

```rust
pub fn check_mir_body_with_dataflow(&mut self, mir: &MirBody) {
    let (_live_in, live_out) = compute_liveness(mir);
    let ever_read = compute_ever_read(mir);  // NEW

    // ... walk basic blocks ...
    // In kill_expired_borrows_dataflow:
    //   for each active borrow's ref_local:
    //     if ref_local is NOT in ever_read:
    //       do NOT kill (preserve GAP-1 — stray borrow stays)
    //     else if ref_local is NOT live_after:
    //       kill (NLL — last use passed)
}
```

### 5.2 The `compute_ever_read` helper

```rust
/// Stage 15.39: Compute the set of locals that are read ANYWHERE in the
/// MIR body. Used by `kill_expired_borrows_dataflow` to preserve GAP-1
/// semantics for never-read ref_locals (their borrows stay alive as
/// "stray" until scope end, matching the legacy path).
pub fn compute_ever_read(mir: &MirBody) -> HashSet<LocalId> {
    let mut ever = HashSet::new();
    for bb in &mir.basic_blocks {
        for stmt in &bb.statements {
            for local in statement_reads(stmt) {
                ever.insert(local);
            }
        }
        for local in terminator_reads(&bb.terminator) {
            ever.insert(local);
        }
    }
    ever
}
```

### 5.3 Modified `kill_expired_borrows_dataflow`

```rust
fn kill_expired_borrows_dataflow(
    &mut self,
    mir: &MirBody,
    live_out: &LiveOutMap,
    ever_read: &HashSet<LocalId>,  // NEW parameter
    bb: BasicBlockId,
    stmt_idx: usize,
) {
    let live_after = compute_live_after_point(mir, live_out, bb, stmt_idx);

    let locals_to_kill: Vec<LocalId> = self
        .borrows
        .active_ref_locals()
        .filter(|local| {
            // GAP-1 preservation: never kill a borrow whose ref_local
            // was never read. The borrow stays as a "stray" until scope
            // end, matching the legacy path's behavior.
            if !ever_read.contains(local) {
                return false;  // do NOT kill
            }
            // NLL: kill if the ref_local is not live after this point.
            !live_after.contains(local)
        })
        .collect();
    for local in locals_to_kill {
        self.borrows.kill_borrows_of_local(local);
    }
}
```

### 5.4 Testing strategy

1. **Re-run the diagnostic tool** after implementing Option B. The
   LEGACY-STRICTER count should drop to ~0 (the 112 cases now agree).
   The DATAFLOW-STRICTER count should also drop to 0 (the false positive
   is avoided).
2. **Run the full conformance suite** — all 5216 tests should pass.
3. **Run the loop-borrow soundness tests** (Stage 15.36 tests) — these
   should still pass (Option B uses dataflow for loop correctness).
4. **Switch the driver** to `check_mir_body_with_dataflow` and re-verify.

### 5.5 Stage plan

- **Stage 15.39**: Implement Option B (`compute_ever_read` + modified
  `kill_expired_borrows_dataflow`). Re-run diagnostic tool to verify
  the LEGACY-STRICTER count drops to ~0. Do NOT switch the driver yet.
- **Stage 15.40**: Switch the driver to `check_mir_body_with_dataflow`.
  Run full conformance suite. If all pass, the NLL migration is complete.
- **Stage 15.41**: Remove `compute_last_use_map`, `kill_expired_borrows`,
  and the legacy `check_mir_body` (now truly dead code). Mark the
  v0.2 Phase 2 Task 7 as COMPLETE.

## 6. Decision Criteria

The decision between Options A/B/C should be based on:

1. **Does the project want real NLL or lexical lifetimes?**
   - If real NLL: Option A (flip the 112 tests).
   - If lexical lifetimes: Option B (preserve GAP-1).
   - If unsure: Option B is the safer default (preserves current behavior).

2. **Is the `&mut self` false positive acceptable?**
   - If Option A is chosen, the false positive MUST be fixed first.
   - Option B avoids the false positive entirely.

3. **What's the effort budget?**
   - Option B: 3-5 days (lowest).
   - Option A: 1-2 weeks (medium, plus false positive fix).
   - Option C: 1-2 weeks (highest, most complex).

## 7. Conclusion

The diagnostic tool (Stage 15.38) revealed two key facts:

1. The project's "NLL" is actually lexical lifetimes with a partial
   last-use optimization (112 LEGACY-STRICTER cases).
2. The dataflow path has a false positive on `&mut self` method call
   chains (1 DATAFLOW-STRICTER case).

Given these facts, **Option B** (keep lexical lifetimes, add "was ever
read" check to the dataflow path) is the recommended reconciliation. It:
- Preserves the project's soundness posture (GAP-1 stays).
- Fixes the real NLL soundness bugs (loops, conditionals).
- Avoids the false positive.
- Uses the existing dataflow infrastructure.
- Is the lowest-effort option.
- Is reversible (future Option A migration remains possible).

The implementation plan (Stages 15.39-15.41) is clear and testable at
each step. The diagnostic tool (Stage 15.38) provides the acceptance
criterion: after Stage 15.39, the LEGACY-STRICTER count should drop
to ~0, and the DATAFLOW-STRICTER count should drop to 0.
